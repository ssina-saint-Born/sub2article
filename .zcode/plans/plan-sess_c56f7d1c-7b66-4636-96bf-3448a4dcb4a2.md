## Phase 4 (revised) — Full Web/Parity — Implementation Plan

### Philosophy shift
Replace "graceful degradation" with genuine parity. Every Electron-only capability now has a real browser-native implementation. Where the browser fundamentally cannot do something (e.g., close the OS window), the feature stays desktop-only — but no mock error ever surfaces in normal use because those buttons simply don't render in web mode.

   Extend `toTesseractLang()` so 'English + Persian (فارسی)' → 'eng+fas'.

### C. `src/components/tabs/ImageOCR.jsx` + `BookProcessor.jsx` — sleek custom dropdown
Replace the plain `<select>` (line 474 in ImageOCR, ~684 in BookProcessor) with a custom dropdown component styled to the app's dark theme (open/close state, radiobutton-style list, existing `surface-*` palette, `transition-all`, `glow-sm` on open). Both components use the shared `OCR_LANGS` list.

## 2. Web-Compatible Cloud OAuth + Upload

### A. NEW: `src/utils/webAuth.js`
**Implicit Grant** (not PKCE; no code exchange, no secret, no server). Access token comes back in URL hash.

**Authorize URLs**:
- Google Drive: `https://accounts.google.com/o/oauth2/v2/auth?client_id=...&redirect_uri=...&response_type=token&scope=https://www.googleapis.com/auth/drive.file&state=...`
- Dropbox: `https://www.dropbox.com/oauth2/authorize?client_id=...&redirect_uri=...&response_type=token&state=...`

**Token storage**: `localStorage` key `subscribe-ai-web-tokens`, shape matches desktop: `{ [provider]: { access_token, expiry_date, _account: { email, name } } }`.

**Flow**:
1. webConnect(provider): `sessionStorage.setItem('oauth.returnTo', window.location.origin + window.location.pathname)`, `sessionStorage.setItem('oauth.provider', provider)`, `sessionStorage.setItem('oauth.state', state)`, then `window.location.assign(buildAuthorizeUrl(...))`.
2. Callback at same origin+path: `new URLSearchParams(window.location.hash.slice(1))` → accessToken, state, expires_in. Validate state, save token+computed expiryDate, fetch account info via fetch (Google `/oauth2/v3/userinfo`, Dropbox `/2/users/get_current_account`), `window.history.replaceState` to clean hash, sessionStorage.removeItem cleanup.
3. `webStatus(provider)`: reads localStorage, returns `{ ok: true, connected: bool, account: {email,name} }`.
4. `webDisconnect(provider)`: optional online revoke (`oauth2.revoke` GET for Google; `dropbox docs` revoke endpoint for Dropbox) + localStorage wipe.

**Provider config (web)**: Vite env vars — `import.meta.env.VITE_GOOGLE_CLIENT_ID` and `import.meta.env.VITE_DROPBOX_APP_KEY`. Build-time inlined; never contains secrets (Implicit Grant doesn't use them). New `.env.example` documents these.

**Uploads (fetch-based)**:
- Google Drive: `POST https://www.googleapis.com/upload/drive/v3/files?uploadType=multipart&fields=id,webViewLink`, `multipart/related` body, `Authorization: Bearer <token>`.
- Dropbox: `POST https://content.dropboxapi.com/2/files/upload`, `Authorization: Bearer <token>`, `Dropbox-API-Arg` header with path/mode/autorename, body = raw bytes.

### B. `src/utils/bridge.js` — replace web-cloud mock with real implementations
```js
cloud: {
  status: (provider) => webStatus(provider),
  connect: (provider) => webConnect(provider),
  disconnect: (provider) => webDisconnect(provider),
  upload: ({ provider, fileName, buffer, mimeType, onProgress }) => webUpload(...),
  isEncryptionAvailable: () => Promise.resolve({ ok: true, available: false }),
}
```
Also fill in real browser fallbacks for `fs` / `window` / `app` / `ocr` so NO method ever returns a "desktop only" mock error in normal flows:
- `window`: keep no-ops (TitleBar won't render these in web).
- `app.openExternal`: already does window.open — keep.
- `ocr.run`: real tesseract.js browser impl via `extractLocal`.
- `fs.writeFile`: convert string contents → Blob → `<a download>` trigger, return `{ ok: true, filename }`.
- `fs.readFileText`: prompt user via hidden `<input type=file>` to pick a file, then read with FileReader, return `{ ok: true, data }`. NOTE: this is Only used by SubtitleProcessor.handleBrowse which ALSO has its own direct `<input>` fallback — so bridge's nooptopl true (no caller hits bridge.fs.readFileText on web). That method keeps its mock `{ ok:false }` — dead code path.
- `fs.showOpenDialog`: keep mock — unused, we already have direct `<input>` fallback.
- `fs.showSaveDialog`: keep mock — unused, `isElectron()` gate handles Export.

### C. `src/hooks/useCloudStorage.js` — zero logic changes
Task 11 routed everything through `bridge.cloud`. Now that `bridge.cloud.{status,connect,disconnect,upload}` have real browser implementations returning the same `{ ok, connected, account }` / `{ ok, fileId, ... }` shapes, `useCloudStorage`'s `if (!res?.ok)` error handling naturally surfaces any OAuth failure (e.g. access_denied) to `addLog('error', ...)` the same way desktop does. No code changes needed. The OAuth connect()'s redirect-navigates-away semantics still work — the Promise just never resolves in the current page (expected; the callback inherits state).
